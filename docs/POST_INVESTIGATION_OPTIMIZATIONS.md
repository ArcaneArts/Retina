# Post-investigation implementation goal

This tracks the implementation goal following the October 19 performance
investigation. It is separate from the completed earlier cycles in
`OPTIMIZATION_INTEGRATION_2026_10.md`. The complete goal remains open.

| Workstream | Current disposition | Remaining work |
| --- | --- | --- |
| Decoration overhead and diagnostics | [Compact GPU continuations](COMPACT_GPU_CONTINUATIONS.md) reduce dense checkpoint retention and CPU replay, fix internal queue handoff, and add opt-in phase/fallback diagnostics. [Early group suspension](EARLY_DECORATION_SUSPENSION_TRIAL.md) was implemented and rejected. [Bounded ready batches](READY_DECORATION_BATCHES.md) with immutable substrate reuse improve matched eight-caller Terralith throughput 1.3–4.9% and are enabled only on Metal with eligible GPU vine programs. Forced batching without such programs regressed two-caller vanilla and is not the default. | Include the selected scheduling policy in the final combined audit. Do not repeat rejected suspension or uncached batching policies unchanged. |
| Material and placement checks | Compiled immutable material sets and bounded sharing are implemented and measured; see [the report](MATERIAL_PREDICATE_OPTIMIZATION.md). Prepared material layouts, repeated-column reuse and biome membership were implemented/tested and [rejected](PREPARED_PLACEMENT_LOOKUP_TRIAL.md): microbenchmarks improved, complete workloads did not justify shipping them. Reproducible patches and negative results are retained. | Other hot-path allocation/dispatch work supported by the new diagnostics; do not repeat the rejected lookup representation unchanged. |
| Effective GPU decoration coverage | Exact vine handoff and fallback pass real-GPU tests. [Detailed diagnosis](VINE_GPU_FALLBACK_TRIAL.md) identifies the dense fixture's 48 supposed overflows as missing material reads. A guard-input prototype was implemented and rejected. [Immutable substrate reuse](READY_DECORATION_BATCHES.md) removes repeated packing/uploads from windowed scheduling while sharing the existing 64 MiB retention budget; shared arena identity handles interleaved regions and lost buffers. | Preserve exact GPU/CPU handoff and fallback during remaining specialization. Do not increase buffers to solve the misclassified missing-input case. |
| Optional LZ4 MCA codec | [Type-4 LZ4 output](MCA_COMPRESSION.md) is implemented with typed records, configuration, framing/checksums, promotion/repair compatibility, whole-pipeline measurements and Minecraft-reader validation. Zlib remains the default because LZ4 increases storage and whole-pipeline results vary. | Include both codec choices in the final combined audit; do not repeat the isolated codec experiment as if the feature were absent. |
| NBT encoding | [Biome metadata reuse](NBT_BIOME_METADATA_TRIAL.md) was implemented, tested and rejected after full-pipeline comparison. [GPU section palettes](GPU_SECTION_PALETTES.md) reuse final-block uploads and classification, preserve exact packed data, and are enabled on Metal with CPU fallback. | Preserve full NBT and lifecycle checks during remaining placement changes; assess any further scan reuse only with a new measured hypothesis. |
| GPU final-section encoding and specialization | [GPU heightmaps](GPU_HEIGHTMAP_TRIAL.md) were implemented/tested and rejected after Terralith regressions. [GPU palettes and compact block output](GPU_SECTION_PALETTES.md) reduce NBT worker time about half and improve repeated eight-caller vanilla throughput 9–10%, with extra readback. [Predecoded placement evaluation](COMPILED_PLACEMENT_EVALUATION_TRIAL.md) was implemented/tested and rejected after repeated vanilla throughput regressions; complete plans and 24,576 full NBT comparisons match. | Include the retained evaluator and backend-specific palette policy in the combined audit. Do not repeat the rejected instruction representation unchanged. |
| Combined integration and documentation | Predicate/continuation/codec/palette/batching cycles have complete-region comparisons. Palette validation includes eight generation callers with two CPU workers, plus actual Minecraft mixed-codec promotion, repairs, edits and malformed-cache atomicity. Placement specialization has a documented rejection, and the ordered-plan harness now includes tick IDs. README and per-cycle evidence are updated. | Run final combined eight-caller checks and matched benchmarks, update the overall report, and perform the full requirement-by-requirement completion audit. |

Each cycle uses its own worktree and PR with squash auto-merge. Preserve unrelated
active worktrees, use local bounded checks, and do not launch the game or trigger
GitHub Actions. Isolated stage savings must not be reported as complete-generator
gains. Recheck current source and merged changes before each subsequent cycle.
